### 5. 安全架构：链下目录隔离与 HMAC 认证（2026-05-12 新增）

| 论文要求 | 当前项目落点 | 说明 |
|---|---|---|
| 链上只存身份，不暴露端点 | `AgentRegistry.sol` endpoint 字段已弃用 | 新注册时 endpoint 传空字符串，合约中标记为"已弃用"。 |

| 防重放攻击 | 5 分钟时间戳偏差校验 | Agent 服务端拒绝超过 5 分钟的请求。 |
| Docker volume 挂载目录 | `docker-compose.agents.yml` | 容器内通过 `/app/agent-directory` 只读挂载访问密钥。 |

## 部分实现或与论文表述存在差距

| 论文内容 | 当前差距 | 建议表述 |
|---|---|---|
| "协调合约部署在目标链上管理任务生命周期、共识逻辑" | AgentRegistry 仅管理 Agent 注册和信誉，任务生命周期仍在 relayer 层。 | 论文实现章节应写"链上已部署 AgentRegistry 合约管理 Agent 身份和信誉，任务协调逻辑仍位于 relayer demo 层"。 |
| "VRF(block_hash || task_id) 可验证随机选择" | 当前 `selectCommittee` 使用区块哈希 + keccak256 伪随机，合约中有 VRF 验证函数但未启用真实 VRF 预言机。 | 写成"VRF-ready committee selection with fallback to blockhash-based pseudorandom"。 |
| "Agent 池动态加入退出、负载约束 load < L_max" | Agent 通过链上合约注册，但没有自动心跳、负载上报、准入和退出机制。 | 后续需要 Agent 健康检查和自动暂停机制。 |
| "独立组织运营的 Agent 进程" | 当前为 Docker 容器内独立进程，但仍在单机上运行。 | demo 展示多容器架构，生产环境需要多机部署。 |
| "A 类型执行 Merkle proof、背书签名校验" | query verifier 做 commitment/header/witness 一致性检查；Fabric 背书签名、真实 Merkle/state proof 仍未完整实现。 | 论文中应区分"原型 witness/commitment 校验"和"完整链证明校验"。 |
| "Commit 阶段和 Reveal 阶段有独立窗口、超时惩罚" | 当前 `sealOpinion()` 同时生成 commit 和 reveal，没有真实 `T_commit/T_reveal`、缺席、扣留揭示、链上验证交易。 | 可保留为审计字段原型，不能宣称完整 commit-reveal 协议。 |
| "仲裁组 k=5，高信誉仲裁者，仲裁也 commit-reveal" | 当前只有一个 `arbitration-01` 规则仲裁器，且不使用独立仲裁委员会。 | 需扩展 ArbitrationAgent 池与仲裁共识。 |
| "信誉 decay、风险缩放、滑动窗口方差、长期策略性检测" | 链上信誉更新有基础评分，但未完整实现论文公式中的 decay、lambda_r 风险缩放和 m=20 窗口检测。 | 需要把论文参数固化为可配置策略并补测试。 |
| "贿赂攻击、联盟防护、经济安全性" | 当前有 settlement/slash 展示，但没有 stake、押金、链上奖励罚没、贿赂成本实验。 | 理论分析已有，工程验证未完成。 |
| "实验环境 8 台 VM、20 验证者、8 收集者、10 仲裁者" | 当前是本机 Docker + 5 验证者；没有多机部署、真实网络延迟、大规模 Agent 池。 | 论文实验章节需要标注为"目标实验配置"或补实验后再写实测结果。 |
| "40% Byzantine 下正确率 96%+" | 目前模拟器默认恶意比例只到 `[0.1, 0.2, 0.3]`；没有固定输出 40% 场景和统计报告。 | 需扩展脚本并保存可复现实验结果。 |
