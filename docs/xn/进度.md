### 3. UI "委员会规模" 说明(排查记录)
- app-query 页显示的"委员会规模"= `negotiationSummary.selectedCommittee.length` = **最终一轮**入选委员会人数。

### 4. 云端 agent 启动问题诊断(port 6008 / b3、b4)
- 现象:`status` 显示 `6008 pid=1417` 但 `/a /b health unreachable`。
- 根因:**过期 PID 文件**。PID 倒挂(6006=2021 新、6008=1417 旧)说明 6008 用的是上次遗留 PID;`start_port` 仅靠 `kill -0` 判活,误判 "already running" 而**跳过 6008**;`multi_agent_service.js` 绑定失败时**静默退出**并留下 PID 文件,正是这个状态。

### 5. ⭐ 脚本/服务加固(本次主要代码改动 —— 见"当前状态")
改动文件 2 个:
- `fabric-chaincode/Relayer/demo/agents/multi_agent_service.js`
  - `app.listen` 后新增 `server.on('error')`:绑定失败(如 `EADDRINUSE`)打印结构化日志(含 `code`)并 `process.exit(1)`,**不再留僵尸**;新增 `exitOnError` 选项(默认 `false`,CLI 入口 `require.main` 传 `true`,保证测试/被引用时不误杀)。
- `scripts/cloud-agents.sh`
  - 新增 `port_healthy()`(curl 根 `/health`)、`pid_is_agent()`(校验 PID 确为本 agent,**防 PID 复用误判/误杀**)。
  - `start_port`:以 **HTTP 健康**判活;启动后轮询确认真在服务(进程死即判失败);失败时打印日志尾部 + 清 PID 文件 + 返回非零。
  - `stop_port`:仅确认是本 agent 才 `kill`;PID 文件始终清理。
  - `status_port`:以 HTTP 为准;**新增 "pid 活着但无 HTTP(stale/hung)" 明确状态**(正是今天遇到的情形)。
  - `start`/`restart`:逐端口汇总失败并返回非零退出码。
- 本地实测(临时目录 + 真起 node bundle 于 6006/6008)**4 场景全过**:① 干净启动 ② 幂等 already serving ③ EADDRINUSE 报 FAILED 且不留僵尸、PID 文件已清 ④ PID 复用不误杀且照常重启。
- 语法检查:`node --check`、`bash -n` 均通过。
