## 二、当前未真正实现或仅实现为原型的部分

虽然已经具备较完整的工程原型，但以下部分仍未达到严格研究方案或论文级实现。

### 1. 多 agent 目前仍是单进程内原型

- 现在的 agent 并不是独立部署的自治智能体网络。
- 当前是单进程内的规则型 runtime 编排。
- 因此它更适合表述为“多 agent 协商原型”，而不是完整的开放式多智能体系统。

### 2. 当前权重机制不是严格 WBFT

- 目前权重分配更接近工程启发式策略。
- 尚未形成严格的加权拜占庭容错数学模型。
- 还没有完整给出加权安全边界、阈值条件与形式化证明。

### 3. 攻击分析仍是启发式

- 隐性合谋与日蚀风险目前通过评分和历史行为模式推断。
- 尚不是形式化攻击检测机制。
- 更适合在论文中表述为“风险识别原型”。

### 4. 激励机制尚未形成真实经济闭环

- 当前 reward/slash 只是 demo 层结算结果。
- 没有真实保证金、链上手续费分成、链上罚没和经济执行逻辑。
- 因此还不能称为完整激励相容机制。

### 5. LightClient-lite 仍然是轻量原型

- 目前仅做区块头顺序提交、哈希连续性和存在性校验。
- 尚未做严格 finality 验证。
- 尚未做共识签名校验或更强的源链共识证明。

### 6. Query proof 仍然不是完整状态证明

- 当前实现是 `prototype witness`。
- 代码中已明确写明：
  - `prototype witness, not full merkle proof`
- 这说明现阶段仍不是 membership proof / non-membership proof 意义下的严格状态证明。

### 7. 链上尚未实现完整查询验证器

- FISCO 侧目前主要完成了 receipt anchor，而不是完整语义验证。
- Fabric 侧也没有将 MA3C 协商规则做成真正的链上验证逻辑。
- 现在更多是“链下生成证明，链上锚定摘要”。

## 三、距离论文还差哪些内容

如果目标是形成一篇严谨的论文，目前还存在以下关键差距。

### 1. 缺少 WBFT 的形式化建模

论文需要明确给出：

- 权重向量 `W = {w_1, w_2, ..., w_n}`
- 基于成功率、响应延迟、故障历史的权重更新函数
- 加权阈值条件
- 加权版 `3f+1` 或等价安全条件的证明

当前工程虽然有 `weight allocator` 和 `reputation store`，但尚不足以直接支撑“WBFT 已被严格实现”的论文表述。

### 2. 缺少系统化的威胁模型章节

论文中还需要单独成节，正式定义：

- hidden collusion
- eclipse attack
- forged result
- replay attack
- withholding / selective response

当前代码里已有这些概念和雏形处理逻辑，但还没有形成完整、标准化的 threat model 表述。

### 3. 缺少激励相容性与博弈分析

论文需要回答的问题是：

- 为什么 agent 长期诚实是最优策略
- 为什么一次性作恶不划算
- 奖励与惩罚如何约束行为

当前只有 demo 结算逻辑，没有完整博弈论建模和经济分析。

### 4. 缺少严格的可验证查询语义

当前 query proof 还不是严格 state proof。

如果论文主打“可信查询结果”或“可验证跨链查询”，那么还需要补齐：

- membership proof / non-membership proof
- 与 source state root 的严格绑定
- 目标侧独立验证 `VerifyQuery(Q, value, proof)` 的更强语义

这是当前距离论文最核心的差距之一。

### 5. 缺少完整链上验证闭环

现在系统已经可以做到：

- query proof 构造
- negotiation proof 构造
- receipt anchor 上链

但还没有做到：

- 目标链完整验证 query proof
- 目标链完整验证 negotiation proof 的业务语义
- 将验证结论直接纳入链上接受逻辑

因此当前更适合表述为“可审计、可锚定、可演示”，而不是“已完成全链上可验证闭环”。

### 6. 缺少系统化实验

论文还需要补充实验设计与数据，包括但不限于：

- agent 数量增加时的协商收敛时间
- 恶意 agent 占比 10% - 30% 时的正确率曲线
- 新 agent 权重演化速度
- 协商与验证的额外开销
- proof 大小、验证时延、存储开销
- 与 baseline 的对比：
  - trusted relayer
  - event-proof query
  - 当前 MA3C 原型

### 7. 缺少研究主线的进一步聚焦

当前项目同时涉及三条线：

- 跨链消息中继
- 可验证跨链查询
- 多 agent 协商与可信决策

工程上可以并存，但论文中必须聚焦主线，否则会导致贡献点分散、论证不集中。

## 四、当前阶段的总体判断

当前项目状态更适合这样表述：

> 已实现 MA3C 的工程原型与可运行演示，包含多 agent 协商、权重/信誉更新、行为分析、协商证明、双向跨链中继与链上回执锚定；但仍未达到论文级完整方案，核心差距在于 WBFT 数学形式化、严格威胁模型、真实激励闭环、完整状态证明，以及系统化实验评估。

这意味着：

- 从“工程原型”角度，当前系统已经具备较强展示与继续迭代价值。
- 从“论文方案”角度，当前已经有较好的骨架，但还需要进一步严格化、形式化与实验化。

## 六、可直接用于论文正文的 Q/T/W 形式化定义

以下内容可作为论文中“MA3C 的 WBFT 风格权重建模”小节的初稿。

### 1. 符号表

| 符号 | 含义 |
| --- | --- |
| `\mathcal{A}=\{a_1,a_2,\dots,a_n\}` | 参与当前协商轮的 agent 集合 |
| `r` | 当前协商轮次 |
| `a_i` | 第 `i` 个 agent |
| `Q_i^{(r)}` | 第 `i` 个 agent 在第 `r` 轮的验证质量分值 |
| `T_i^{(r)}` | 第 `i` 个 agent 在第 `r` 轮的信任分值 |
| `A_i^{(r)}` | 由验证质量归一化得到的质量权重 |
| `B_i^{(r)}` | 由信任分值归一化得到的信任权重 |
| `W_i^{(r)}` | 第 `i` 个 agent 在第 `r` 轮的最终投票权重 |
| `\alpha,\beta` | 质量权重与信任权重的调节系数，满足 `\alpha+\beta=1` |
| `s_i^{(r)}` | 第 `i` 个 agent 截至第 `r` 轮的累计正确轮数 |
| `m_i^{(r)}` | 第 `i` 个 agent 截至第 `r` 轮参与总轮数 |
| `\ell_i^{(r)}` | 第 `i` 个 agent 在第 `r` 轮的响应时延 |
| `L_i^{(r)}` | 由响应时延映射得到的时延得分 |
| `\rho_i^{(r)}` | 第 `i` 个 agent 的风险惩罚项 |
| `v_i^{(r)}` | 第 `i` 个 agent 在第 `r` 轮的投票结果，取值于 `\{0,1\}` |
| `\tau` | 加权通过阈值，本文取 `\tau=2/3` |
| `\mathcal{H}` | 诚实 agent 集合 |
| `\mathcal{B}` | 拜占庭 agent 集合 |

### 2. 质量分值与信任分值定义

受参考论文中“质量权重 + 信任权重”的双分量加权思想启发，本文将 MA3C 中 agent 的投票能力拆解为验证质量和长期信任两个维度。

首先，定义第 `r` 轮的时延得分为

$$
L_i^{(r)}=\frac{1}{1+\ell_i^{(r)}/\lambda},
$$

其中 `\lambda>0` 为时延尺度参数。该定义保证 `L_i^{(r)}\in(0,1]`，且时延越低，得分越高。

进一步地，定义第 `i` 个 agent 在第 `r` 轮的验证质量分值为

$$
Q_i^{(r)}=\big((1-\eta)\,Q_i^{(r-1)}+\eta\,\hat{q}_i^{(r)}\big)\cdot L_i^{(r)},
$$

其中 `\eta\in(0,1]` 为平滑系数，`\hat{q}_i^{(r)}\in[0,1]` 表示本轮观测到的即时验证质量。对 MA3C 而言，`\hat{q}_i^{(r)}` 可由“该 agent 的判断是否与最终提案一致”以及其置信度共同决定。若其判断与最终提案一致，则 `\hat{q}_i^{(r)}` 取较高值；否则取低值或零值。

其次，定义长期信任分值为

$$
T_i^{(r)}=\frac{s_i^{(r)}+\mu}{m_i^{(r)}+\nu}\cdot \big(1-\rho_i^{(r)}\big),
$$

其中 `\mu,\nu>0` 为先验平滑参数，`\rho_i^{(r)}\in[0,1)` 为风险惩罚项。该式表示 agent 的信任度由历史正确率决定，并根据其异常行为风险进行折减。对于 MA3C，`\rho_i^{(r)}` 可由隐性合谋风险、日蚀风险和故障次数共同估计。

### 3. 质量权重、信任权重与最终投票权重

参考 WBFT 的双分量归一化设计，定义第 `r` 轮的质量权重与信任权重分别为

$$
A_i^{(r)}=\frac{Q_i^{(r)}}{\sum_{j=1}^{n}Q_j^{(r)}},
\qquad
B_i^{(r)}=\frac{T_i^{(r)}}{\sum_{j=1}^{n}T_j^{(r)}}.
$$

于是，第 `i` 个 agent 在第 `r` 轮的最终投票权重定义为

$$
W_i^{(r)}=\alpha A_i^{(r)}+\beta B_i^{(r)},
\qquad
\alpha+\beta=1,\ \alpha,\beta\in[0,1].
$$

由定义可知，

$$
\sum_{i=1}^{n}W_i^{(r)}=1.
$$

这表明 `W_i^{(r)}` 构成一个标准化权重向量，能够直接用于加权投票判定。

### 4. 加权通过规则

设第 `i` 个 agent 在第 `r` 轮对候选提案的投票结果记为 `v_i^{(r)}\in\{0,1\}`，其中 `1` 表示支持提交，`0` 表示不支持提交。定义该轮的加权支持值为

$$
Y^{(r)}=\sum_{i=1}^{n}W_i^{(r)}v_i^{(r)}.
$$

本文采用加权拜占庭容错式的提交规则：

$$
Y^{(r)}>\tau,\qquad \tau=\frac{2}{3}.
$$

即当且仅当支持提交的累计权重大于总权重的三分之二时，系统认为该轮提案达成加权共识并进入提交状态。若仅等于 `2/3`，则不视为通过，这样可以避免边界条件下的歧义。

### 5. 加权诚实多数安全性命题

**命题 1（加权诚实多数安全性）**  
设某一轮协商中，诚实 agent 集合为 `\mathcal{H}`，拜占庭 agent 集合为 `\mathcal{B}`，且满足

$$
\sum_{a_i\in\mathcal{H}}W_i^{(r)}>\frac{2}{3},
\qquad
\sum_{a_i\in\mathcal{B}}W_i^{(r)}<\frac{1}{3}.
$$

若所有诚实 agent 对同一合法提案投支持票，即对任意 `a_i\in\mathcal{H}` 有 `v_i^{(r)}=1`，则任何不被诚实多数支持的伪造提案都无法达到提交阈值 `\tau=2/3`。因此，在上述条件下，MA3C 的加权投票结果对拜占庭 agent 的伪造或串谋具有安全性。

**证明思路：**  
由于所有诚实 agent 的累计权重大于 `2/3`，故合法提案至少可获得

$$
Y_{\mathrm{honest}}^{(r)}\ge \sum_{a_i\in\mathcal{H}}W_i^{(r)}>\frac{2}{3},
$$

从而合法提案可以通过加权提交阈值。另一方面，任何仅由拜占庭 agent 主导的伪造提案，其最大可获得支持权重至多为

$$
Y_{\mathrm{byz}}^{(r)}\le \sum_{a_i\in\mathcal{B}}W_i^{(r)}<\frac{1}{3},
$$

显然无法单独越过 `2/3` 门限。即使拜占庭 agent 尝试制造冲突提案，只要诚实 agent 不对该伪造提案投支持票，则其累计支持权重仍不足以达到加权提交条件。因此，在诚实 agent 权重严格占优的前提下，系统不会接受仅由拜占庭 agent 支持的错误提案。

### 6. 论文中的解释口径

正文中可将上述模型概括为：

> 本文借鉴 WBFT 的双分量加权思想，将 MA3C 中 agent 的投票能力建模为验证质量与长期信任的凸组合。其中，验证质量反映 agent 在当前轮次中对跨链证据的判断有效性及响应时效性，长期信任反映其历史正确率与风险水平。通过对两类分量分别归一化并线性组合，得到每一轮的自适应投票权重向量 `W^{(r)}`。在此基础上，本文采用严格大于 `2/3` 的加权门限作为提案提交条件，并证明当诚实 agent 的累计权重占优时，拜占庭 agent 无法凭借伪造或串谋使错误提案通过。
