# P1 多钱包锚定正式对照

## 结论

在同一单机 Fabric/FISCO 原型和相同供应链正常负载下，四钱包轮询、钱包内串行的锚定策略缓解了单账户 nonce 串行瓶颈。正式运行完成并发 1/2/4/8/16 各 3×20 个计量查询及 2 个预热查询，共 300/300 个计量查询和 310/310 份链上锚定回执。

按“相邻并发吞吐增益低于 10% 且 p95 增长超过 25%”的预注册判据，单钱包在并发 2 首次饱和，四钱包在并发 8 首次饱和。

## 审计核验

五个并发档的 SQLite 数据库完整性均为 `ok`。独立 Python 审计器对每库 62 份回执完成重构和锚点匹配，合计 310/310；1,550 个成功证据节点和 310 个服务输出均为显式绑定，1,240/1,240 个删除节点、替换输出、错误版本和删除证据变异均被检出并定位。所有 310 个交易哈希唯一，五档均使用 4 个签名者，`gasUsed` 最小值和最大值均为 35,166。

## 证据边界

- 两组结果来自同一主机和相同工作负载，但运行日期不同，未采用随机交错的 A/B 顺序。
- 四个钱包按轮询分配，每个钱包内部仍串行；结果证明的是该原型中账户级并行化的效果，不是 FISCO-BCOS 平台吞吐上限。
- 额外三个钱包在实验进程内临时生成，私钥未写入结果；生产环境应使用机构密钥管理与正式 nonce 协调策略。
- 当前尚无第二机器或跨地域重复数据。
