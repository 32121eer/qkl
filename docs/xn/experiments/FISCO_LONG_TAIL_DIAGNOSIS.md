# FISCO 物理暂停场景长尾归因报告

归因日期：2026-09-01

## 结论

物理暂停实验中周期性出现的约 6 s 端到端长尾，主要由暂停节点恰逢当前 PBFT 提议者时触发的约 3 s 共识超时与视图切换造成，而不是 DAG 调度、SDK 端点重连或锚定队列等待造成。端到端观测还包含固定约 1.5 s 的失效证据端点超时，以及查询执行、命令控制和锚定的常规开销，因此最终表现为约 6 s。

该结论只适用于本实验的四节点 FISCO-BCOS PBFT、`leader_period=1`、`consensusTimeout=3000 ms` 和单节点 `SIGSTOP/SIGCONT` 配置，不能外推为其他共识配置或真实跨地域网络的固定行为。

## 证据链

### 1. 长尾按区块呈稳定周期

原始物理故障运行位于 `semantic-query-physical-fault-runs/2026-08-25T01-52-36-106Z/`。FISCO node0 暂停的 20 次运行中，长尾出现在第 2、5、8、11、14、17 次计量查询，对应区块 663、666、669、672、675、678，即每 3 个锚定区块出现一次。这种按区块号稳定重复的模式与轮转提议者相关，而不符合随机网络重连抖动。

### 2. 长尾不在 DAG 执行阶段

旧物理故障运行的 DAG 执行时间稳定在约 1.51 s。新增韧性运行 `semantic-query-live-resilience-runs/2026-09-01T07-55-45-402Z/` 中，首个 FISCO 重同步场景的端到端时间为 6,253.658 ms，但回执内 DAG 时间仅为 1,515 ms；锚定区块为 1183。其余四次同场景的端到端时间为 2,800.431–3,268.020 ms。这排除了 DAG 关键路径作为周期性额外约 3 s 延迟的来源。

### 3. PBFT 日志直接记录 3 s 超时与视图切换

四节点网络日志声明 `consensus_type=pbft`、`leader_period=1`、`consensusNodesSize=4` 和 `consensusTimeout=3000`。在新运行区块 1183 提交前，node3 日志依次出现：

- 2026-09-01 07:56:05.173：`broadcastViewChangeReq` 与 `After onTimeout`，未封装交易数为 1，超时配置为 3000 ms；
- 2026-09-01 07:56:05.200：`reachNewView`；
- 2026-09-01 07:56:05.728–07:56:05.737：区块 1183 执行并提交完成。

原始物理运行也在周期性长尾对应区块附近重复出现相同日志。例如区块 666、669、672、675、678 前分别记录 `After onTimeout` 和 `reachNewView`，且均带有 `consensusTimeout=3000`。这构成“暂停提议者—等待共识超时—视图切换—新区块提交”的直接时间线。

### 4. SDK 重试与锚定队列不是主因

故障查询中的两个 FISCO 证据节点均在第二候选端点成功，证据阶段约 1.5 s 后已经完成切换；长尾额外时间出现在向仍存活的锚定端点提交交易后。新运行的首个长尾样本锚定服务阶段约 3.60 s，而锚定队列等待接近 0 ms。后续非长尾样本的锚定服务阶段仅数十毫秒。因此：

- SDK 候补端点重试解释固定证据超时，但解释不了按区块周期出现的额外约 3 s；
- 单钱包锚定队列在该串行实验中没有积压；
- PBFT 视图切换与额外延迟的时间、周期和持续时间均一致。

“FISCO 单节点暂停场景的周期性长尾与 PBFT 提议者轮转一致；共识日志在对应区块提交前记录 3,000 ms 超时和视图切换。结合约 1.5 s 的失效证据端点超时，端到端时延约为 6 s。该结果是本四节点单机配置的故障机理观测，不代表其他部署的固定时延。”
