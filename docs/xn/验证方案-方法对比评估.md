## 0. 把"更好"拆成可证伪命题

不证"我的好",而证"在指标 X 上、在条件 C 下,本方法显著优于基线 B,且差距来自机制 M"。
每条命题对应一组实验、一个判据、一种失败即推翻的方式。

| 编号 | 命题 | 主指标 | 判据(优于基线即成立) | 推翻条件 |
|---|---|---|---|---|
| **H1 容错上界** | 加权共识比等权/PBFT 容忍更高恶意比例 | 正确率 vs 恶意比例曲线 | 在 30–45% 恶意下正确率显著高于等权多数与 PBFT | 高恶意区正确率不高于基线 |
| **H2 攻击下正确性** | 40% 拜占庭下正确率 ≥ 96%,远高于等权(~60%) | correctness / falseAccept | MA3C 与等权差值 Δ 的 95%CI 不含 0 且 >25pp | Δ 不显著或方向相反 |
| **H3 优势来源** | 优势来自"置信度加权+信誉+异构",非调参 | 消融各档正确率 | 去掉任一机制正确率显著下降 | 去掉机制后无明显下降 |
| **H4 激励相容** | 诚实+如实置信度是占优策略(经验验证理论) | 各策略长期累计收益 | 诚实策略累计信誉收益严格最高 | 搭便车/虚报置信度收益 ≥ 诚实 |
| **H5 成本可接受** | 安全提升的延迟/通信代价有界 | 乐观延迟、链上 tx 数 | 乐观延迟 < 基线 + 可接受 Δ;tx 数符合 2n+3 模型 | 延迟/tx 数爆炸性增长 |
| **H6 攻击经济性** | 策略性对手被快速检出,合谋成功率极低 | 检测延迟(任务数)、合谋成功率 | 8–12 任务内检出;合谋成功率 < 10⁻³ | 检出慢或合谋频繁得手 |

H1/H2/H3 是"更有效"的硬核;H4/H6 兑现论文博弈论部分;H5 回应"代价"质疑。

## 1. 对照基线(必须在同一 harness 内实现 —— 当前缺口)

现有 simulator 只有 MA3C。**先补齐基线策略,共用同一任务流、同一 RNG 种子、同一 agent 误差模型**,才能做配对比较。

| 基线 | 决策规则 | 论文对应 | 实现要点 |
|---|---|---|---|
| **B0 单一中继** | 随机选 1 个 agent,其判断即结果 | "单一中继" | 无共识;恶意/出错即直接错 |
| **B1 等权多数投票** | n 个 agent,1 票/人,过半即定 | "等权委员会" | 无信誉、无置信度权重 |
| **B2 PBFT 式** | 需 2f+1 一致(f=⌊(n-1)/3⌋) | "标准 PBFT" | 容错门槛更严,达不到即超时/仲裁 |
| **B3 信誉加权(无置信度)** | 权重=rep,不乘 confidence | 消融对照 | 隔离"置信度"贡献 |
| **B4 静态委员会** | 固定委员会,无 VRF 轮换 | 消融对照 | 隔离"VRF 轮换"贡献 |
| **MA3C(本方法)** | 权重=rep×confidence,VRF选组,commit-reveal,异构 | 本方案 | 现有实现 |

> B3/B4 既是基线也是消融档(H3 用)。所有基线吃**同一份** `buildAgentPopulation` 输出和同一 `taskValid` 序列,确保差异只来自决策规则。

## 2. 指标体系

**正确性 / 安全**
- `correctnessRate`:终态与真值一致的比例(主指标)
- `falseAcceptRate`:无效证据被 COMMIT(最危险,安全性指标)
- `falseRejectRate`:有效证据被 REJECT(活性/可用性指标)

**性能 / 成本**
- 乐观路径延迟、仲裁路径延迟、p95 延迟、平均轮数 `avgRounds`
- 链上交易数(乐观 2n+3 / 仲裁 2n+2k+4)、每任务存储字节
- 吞吐(tasks/s,受 N×L_max/n 约束)

**抗对抗 / 经济**
- 策略性对手**检测延迟**(从发动到选择概率减半所需任务数)
- 合谋**成功率**(每任务)、合谋**检出率**
- 攻击成本估计(贿赂阈值 B_threshold,兑现定理3)

**机制效度**
- 各策略(诚实/搭便车/虚报置信度/恶意)的**长期累计信誉收益**(兑现 H4)
- 错误相关系数 ρ(异构 vs 同构,兑现"异构降相关"论点)

## 4. 两层评估(关键:别只靠仿真)

**Tier-1 仿真层(大规模、可扫参)** —— 跑 E1–E7,出统计曲线。
快、可重复、能扫到 n=61 和 1000+ 任务。**但单独不足以服人**(行为模型是假设)。

**Tier-2 真链层(小规模、端到端、锚定外部效度)** —— 在已跑通的 Fabric↔FISCO + 13 个真实 agent(5本地+8云端)上:
- 跑 E2 的小规模版(n=5/7,注入 1–2 个真·恶意 agent),实测延迟、tx hash、queryId。
- **用真 LLM 调用**(`llm_client.js`)采集 C 类语义 agent 的**真实误差率与置信度分布**,回填到 Tier-1 仿真的 agent 误差模型 —— 这一步把仿真从"拍脑袋"变成"校准过"。
- 复用 `BATCH-TEST-0099` / `BATCH-APPLE-0001` 既有链上记录,构造"有效查询"与"被篡改证据/过期高度"的无效查询各一批。

> Tier-2 的意义:论文最致命的质疑是"仿真自证"。用真链 + 真 LLM 校准误差率,把 Tier-1 的关键点(如 40% 恶意正确率)在真系统上复现一个点,外部效度就立住了。

## 5. 消融:证明优势来源(H3,最容易被攻、也最有说服力)

逐项关闭、单变量对比,看正确率/falseAccept 掉多少:

| 档位 | 改动 | 预期(若机制有效) |
|---|---|---|
| 全量 MA3C | — | 基准最优 |
| −置信度 | 权重=rep(=B3) | 高恶意区正确率下降 |
| −信誉 | 权重=confidence | 策略性对手区退化 |
| −异构 | 全用同类 agent | ρ 上升、正确率下降 |
| −VRF 轮换 | 静态委员会(=B4) | 合谋成功率上升 |
| −commit-reveal | 明文同时投票 | 从众攻击下退化 |
| 全部关闭 | ≈ 等权多数(=B1) | 退化到 B1 水平 |

"全部关闭 ≈ B1"是一个干净的自洽性检查:说明各机制叠加确实是优势来源。

## 6. 统计方法学(现状是单种子确定性,必须升级)

现有 `runResilienceBenchmark` 用单一基种子 + 固定 trials。要发表级:

1. **多独立种子**:每条件 ≥30 个独立种子(E1/E2 用 ≥200 任务),报告**均值 + 95% 置信区间**,不要只报点值。
2. **配对比较**:同种子下 MA3C 与基线跑同一任务流 → 用**配对检验**(paired t / Wilcoxon)算 Δ 的显著性与效应量(Cohen's d)。
3. **预注册判据**:H1–H6 的判据(第 0 节)在跑数前固定,避免事后挑数。
4. **敏感性分析**:θ∈{0.65,0.70,0.75}、rep_max/rep_min∈{1.5,2,3}、c_min 等关键参数各扫一遍,证明结论对参数不脆弱。
5. **随机种子与版本归档**:每次出数把 seed、git commit、参数、原始 JSON 存档(扩展 `--output`)。

## 7. 构造效度风险与对策(审稿人会问的)

| 风险 | 现状 | 对策 |
|---|---|---|
| **行为模型自证** | 恶意/诚实行为手工调参(simulator.js:180-207),优势可能是"喂"出来的 | 用 Tier-2 真 LLM 校准误差率;把行为模型参数**与方法解耦**并公开;做参数敏感性 |

| **置信度真实性** | confidence 是合成的 | 用真 LLM 的 logprob/自评作为 confidence 来源,验证 PCP 假设 |

## 10. 首轮实测发现(2026-06-14,基线 harness 上线后)

harness 已实现并跑出数据(`demo/experiments/comparative_runner.js`、`scripts/run_comparative_experiments.js`,
12 项单测通过)。**第一次配对对比就推翻了论文的核心对比主张**,记录如下——这些是必须先解决的硬问题:

### 发现 1:论文"96% vs 等权 60%"在当前行为模型下不成立,甚至反转
- 40% 恶意、n=5、新信誉:**等权多数 / PBFT = 100% 正确,MA3C 仅 23%**。
- 根因:仿真器把诚实 agent 建成**确定性永远正确**,40%<50% ⇒ 诚实恒为多数 ⇒ 朴素多数已完美;
  而 θ=0.70 让 MA3C 在"3诚实 vs 2恶意"加权比≈0.65 时够不到阈值 → 判 OBSERVE → 记为错。
- **任何审稿人拿这套代码一跑,会发现 MA3C 被最朴素基线支配。** 这是最高优先级问题。

### 发现 2:θ 阈值 + "OBSERVE=错"的打分对 MA3C 不公平
- MA3C 把够不到 θ 的任务判 OBSERVE,真实协议里这是**触发仲裁(Phase 4)**,不是失败。
- 当前打分把"安全的弃权升级"误记为"错误",系统性低估 MA3C。
- **真正稳健成立的是安全性指标**:MA3C 的 `falseAccept` 在所有场景下都低一个数量级
  (如 honestErr=0.12 时 MA3C **1.6%** vs 等权 **15.6%** vs 单中继 **23%**)。MA3C 不是更"对",是更**安全**。

### 发现 3:信誉学习存在冷启动死锁,仲裁是闭环的承重件
- 恶意占多数(55–60%)的序列场景,MA3C 仍 ~1.6%,**没靠信誉翻盘**。
- 根因:`reputation_store.updateFromRound` 用 `finalDecision` 评分;若结果是 OBSERVE,
  无人 match → 信誉学不到谁诚实 → 永远到不了决定性结果。**学习需要决定性结果,决定性结果又需要学习** = 死锁。
- 真实系统靠**仲裁**打破死锁(仲裁决定性 + 反哺 ground truth)。**仿真器漏了仲裁**,所以学习闭环断了。

### 由此修正的研究策略(取代第 0 节部分命题的措辞)
1. **把主张从"更高正确率"改写为"更低误受率 / 更高安全性,代价是升级仲裁的延迟"** —— 这是真正复现得了的卖点。
2. **仿真必须建模仲裁路径(Phase 4)**:OBSERVE → 仲裁委员会决定性裁决 + 回灌信誉。这是让正确率公平、让学习闭环成立的关键缺口。下一步最高优先级。
3. **诚实 agent 必须带概率错误率 p_i**(论文 §V-A 自己假设了,仿真却做成零错误 —— 内部矛盾):harness 已加 `honestErrorRate` 开关。
4. **构造能让加权真正赢的 regime**:误差相关(同类 agent 共错)、策略性对手(高信誉后翻脸)、恶意可累积权重 —— 仅"诚实恒为正确多数"时加权无用武之地。

> 一句话:harness 没有"证明"方法更好,而是诚实地告诉你**当前证不出来、缺什么才能证**。
> 下一步先补仲裁模型 + 概率误差,再重跑 H1/H2;安全性(falseAccept)这条线现在就能写。

## 11. 仲裁补全后:核心主张已复现(2026-06-14,同日)

按发现 3 的指引,给仿真补了**仲裁路径(Phase 4)**:OBSERVE → 独立高质量仲裁委员会(k=5、
误差率为线验证者的 0.3×、θ_arb=0.75)决定性裁决,并**用仲裁结果回灌信誉**。仲裁不是预言机
(自身有误差),代价是延迟(乐观 8s → 仲裁 21s),全部计量。结果(seeds=150–200,配对检验):

### 决策对比(新信誉,40%恶意,n=5,诚实误差 0.12)
| 方法 | 正确率 | 误受率 | 升级率 | 平均延迟 |
|---|---|---|---|---|
| **MA3C** | **95.9%** | **1.8%** | 80.7% | 18.9s |
| 等权多数 B1 / PBFT B2 | 67.8% | 16.3% | 0 | 8.0s |
| 单中继 B0 | 52.5% | 23.8% | 0 | 8.0s |

- **MA3C vs 等权:+28.0pp,CI[26.6, 29.4],p<0.01,Cohen's d=2.75** —— 论文"~96% vs ~60%"复现。
- 安全性:误受率 16.3% → 1.8%(↓14.5pp)。
- 诚实代价:升级 80.7%、延迟 ~19s(新信誉下大量 case 够不到 θ,只能升级)。

### 序列对比(信誉演化,30%恶意,n=7,诚实误差 0.12)
| 方法 | 正确率 | 误受率 | 升级率 | 平均延迟 |
|---|---|---|---|---|
| **MA3C** | **99.8%** | **0.0%** | **11.7%** | **9.6s** |
| 等权多数 B1 | 88.8% | 5.7% | 0 | 8.0s |
| 纯信誉 B3 | 87.9% | 0.0% | 0 | 8.0s |
| PBFT B2 | 52.3% | 0.7% | 0 | 8.0s |
| 单中继 B0 | 62.7% | 18.8% | 0 | 8.0s |

- **死锁打破**:信誉学会谁诚实后,验证轮自己过阈值,**升级率 80.7%→11.7%、延迟 18.9s→9.6s**,成本随时间摊销。
- MA3C vs 纯信誉 B3:+11.9pp,p<0.01,d=3.88;vs 等权 +11pp。

### 消融:仲裁是承重件(锁进单测)
关闭仲裁(`--no-arbitration`),MA3C 正确率 **95.9% → 15.9%**(够不到 θ 的全卡在 OBSERVE)。
证明 MA3C 的正确率优势确实来自"加权共识 + 仲裁升级"这套机制,而非调参。

### 由此确定的论文叙事(可写、可复现)
1. **主卖点 = 安全性**:误受率比所有基线低一个数量级(16% → ~2%,序列下 → 0%),且**始终成立、不依赖信誉成熟**。
2. **正确率优势 = 加权共识 + 仲裁升级**:新信誉下靠仲裁兜底拿到 96%,信誉成熟后靠加权直接拿到 99.8%。
3. **诚实的代价 = 延迟**:乐观 8s vs 仲裁 21s;升级率随信誉成熟从 80% 降到 12%,代价摊销。
4. **公平性声明**:仲裁是 MA3C 协议自带、基线没有的升级路径(整协议 vs 整协议对比);已用 `--no-arbitration` 消融证明其承重,并量化延迟代价,非"免费预言机"。

## 12. 误差率校准:从"拍脑袋"到"数据派生"(2026-06-14)

仿真里唯一没被真实数据锚定的两个参数 —— 线验证者诚实误差率 `honestErrorRate`、
仲裁者/验证者误差比 `arbiterErrorFactor`(原固定 0.12 / 0.3)—— 现在做成了**一条命令测出来**:

- 校准逻辑:`demo/experiments/calibration/llm_calibration.js`(标注证据批 + 误差/置信度统计)
- 采集脚本:`scripts/collect_llm_calibration.js` → 产出 `calibration.json`
- 自动接线:`comparative_runner` 读 `CALIBRATION_FILE`,用实测值替换默认(无需改代码)

**标注基准**:1 类有效 + 5 类篡改(crypto_fail / missing_txhash / missing_payload /
height_out_of_range / payload_mismatch),每类带 ground truth。走**生产同款** `llm_client.verify()`;
仲裁误差 = k 次独立调用的多数表决误差。输出 `calibratedParams{honestErrorRate, arbiterErrorFactor,
meanConfidenceCorrect, meanConfidenceWrong}`。

**本机限制(已核查)**:macOS 上 `OPENAI_API_KEY` 空、FISCO/Demo API/Ollama 均不可达、真链在 WSL,
故**真 LLM 校准跑不了**。已用 `mock` 后端跑通管线(冒烟),且 mock 结果本身就印证了为何需要真 LLM:

| 篡改类型 | mock errorRate | 说明 |
|---|---|---|
| none / crypto_fail | **0** | 规则匹配能抓(字段齐全 / 预检 FAIL) |
| height_out_of_range / payload_mismatch / missing_* | **1.0** | **mock 抓不到语义不一致** —— 正是 C 类语义推理需要 LLM 的地方 |

mock 给出的 `honestErrorRate=0.667` 是 mock 缺陷(规则agent做不了语义判断),**不是真 LLM 误差**。

**待你在 WSL 那台执行(配好后端即得真值)**:
```bash
AGENT_LLM_BACKEND=ollama AGENT_LLM_MODEL=llama3.1:8b \
  node scripts/collect_llm_calibration.js --repeats=10 --output=demo/experiments/calibration/calibration.json
# 然后所有对比实验自动用真值:
CALIBRATION_FILE=demo/experiments/calibration/calibration.json \
  node scripts/run_comparative_experiments.js --sweep --seeds=300
```
拿到真 `honestErrorRate` / `arbiterErrorFactor` 后,§11 的结论就完全建立在实测误差模型上,"仿真自证"质疑彻底消除。

## 13. 真 agent 实验:用实际实现而非仿真验证优越性(2026-06-14)

不再用数值仿真的手工行为模型,改用**实际 production 的 `VerifierAgent` 代码**产生每一条意见
(`useLLM:false` → 真实 `evaluateChecks→decide→calculateConfidence`),真实拜占庭行为注入
(`behavior:'always_approve'` 等),真 arbiter agent 跑仲裁。这些真意见再由 MA3C 与基线 B0–B2 聚合对比。

- 实现:`demo/experiments/real_agent_experiment.js`、`scripts/run_real_agent_experiment.js`
- 测试:`__tests__/demo/experiments/real_agent_experiment.test.js`(锁定真agent行为 + 60%拜占庭结论)
- 范围:无 LLM 时规则agent能决断**密码学/结构有效性**(预检、采集者法定数、proof),故用
  VALID vs 密码学篡改两类任务,聚焦**共识对拜占庭的鲁棒性**(语义层误差另由 §12 校准)。

### 真 agent 拜占庭扫描(always_approve 伪造接受攻击,n=5,30 trials × 10 tasks)
| 恶意比例 | MA3C | 等权多数 B1 | PBFT B2 | 单中继 B0 |
|---|---|---|---|---|
| 20% | 100% / 误受 0% | 100% | 100% | 90% / 误受 10% |
| 40% | 100% / 误受 0%(升级 50%) | 100% | 100% | 80% / 误受 20% |
| **60%(恶意过半)** | **100% / 误受 0%**(升级 50%) | **50% / 误受 50%** | **50% / 误受 50%** | 70% / 误受 30% |

**决定性结论(恶意过半 60%)**:
- 等权多数与 PBFT **彻底沦陷**:3/5 恶意 always_approve 凑成多数 → 伪造证据被 COMMIT,误受率 50%。
- MA3C **100% 正确、0% 误受**:θ=0.70 挡住恶意多数(加权 acceptRatio≈0.649 够不到阈值)→ 触发仲裁
  → 真 arbiter REJECT。**MA3C vs 等权:+50pp,CI[50,50],p<0.01。**
- 这是加权 BFT 在恶意过半时碾压简单多数的教科书结论,**由真 agent 代码跑出**,非行为模型。

### 与数值仿真(§11)的关系
- §11 数值仿真:可扫大规模 + 注入语义层概率误差,给统计曲线;但行为是建模的。
- §13 真 agent:每条意见来自实际 `VerifierAgent.execute()`,**外部效度最强**;但规则层确定性、
  honest 误差为 0,故聚焦共识鲁棒性。两者互补:真 agent 锚定实现可信度,仿真补语义层与规模。
- 论文应**两个都放**:真 agent 表(本节,可信)+ 仿真曲线(§11,规模)+ 误差校准(§12,堵自证)。
